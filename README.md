# Основы кибербезопасности

Курс содержит портал, книгу теории `theory`, единый банк заданий `task` и
семинарские материалы `seminars`. QRC namespaces theory/tasks/practice сохранены;
URL подпроектов соответствуют этим папкам. Устойчивый course.id задаётся только
в корне: cybersecurity. Условия не дублируются на страницах назначения.

Требуются Quarto >=1.10.18, Python 3 для проверок CI
и CUE для экспортных пакетов. Установка конкретных новых
выпусков выполняется штатным `quarto add` по командам CI/install-extensions.sh.

Закреплённый набор установленных инструментов:

| Инструмент | Выпуск | Проекты |
| --- | --- | --- |
| Core, Presentation, Navigation | 3.0.2 | Корень, theory, task, seminars |
| Publisher | 4.0.1 | Корень |
| Reference Catalog | 2.2.1 | Корень, theory, task, seminars |
| Download | 1.1.1 | task |

В каждом самостоятельном проекте включён штатный `fail-if-warnings: true`: предупреждения авторской сборки завершают её с ошибкой. Для составного курса настройка задана в корне и каждом подпроекте, поскольку корневой CLI-флаг не передаётся отдельным запускам Quarto автоматически. Диагностика инструментов содержит код и контекст ошибки; исходный вывод Quarto, Pandoc и других процессов сохраняется в журналах.

```sh
bash CI/install-extensions.sh
quarto render --profile student
quarto render --profile full
quarto preview --profile student --no-watch-inputs
```

Student публикуется; full остаётся локальным. В book используются отдельные полные
списки глав каждого профиля. Full включает два имеющихся авторских черновика
контрольных; в них пока нет готовых условий/назначений, поэтому они не объявляются
готовым экспортом. Их источники сохранены. Задание о контрольных суммах находится
в `task/data-integrity/checksum.qmd`. Остальные тематические заготовки также сохранены.

Одна презентация семинара публична в обоих профилях: общие notes, скрытые details
и режим страницы не требуют повторной сборки. Каталог семинаров — обычный HTML
в том же native website, отдельный документ — Reveal. Штатные уровни ##/###,
порядок слайдов и QRC targets сохраняются.

## Экспорт существующей работы

```sh
quarto run _extensions/Afonenko-Course-Tools/course-core/entrypoints/export.ts --book task --work sec-work-data-integrity-backup --output _generated/backup.json
```

Полный и публичный пакеты содержат только назначенные задания и ресурсы работы.
Контрольные исходники не зависят от student-публикации; полный HTML для экспорта
не требуется. Дополнительные адаптеры устанавливаются отдельно при выборе соответствующего
маршрута: Print 0.2.1, Moodle 0.2.1, PrairieLearn 2.1.1, Cloud 2.1.1.
Эти выпуски входят в согласованный набор; текущий курс их не активирует. Правила оценивания и доступа всегда платформенно специфичны.

Текущая миграция не публикует курс и оставляет PR открытым. Локальные проверки
контролируют native inputs профилей, QRC/local links, отсутствие full/закрытых
пакетов в student resources и время полной сборки (предел 15–20 минут).

## CI и диагностика сборки

Служебные скрипты находятся в `CI/` и исключены из ресурсов сайта.
CI использует установленные в репозитории расширения; `CI/install-extensions.sh`
нужен для их явного обновления. Проверки запускаются на двух версиях Quarto:
student → full → student, затем `python3 CI/site.py _site-student _site-full`.

Каждая сборка — отдельный шаг. При ошибке CI сохраняет полные логи
`ci-logs`, включая отладочный вывод Quarto, и трассу подпроектов.
Локально ту же сборку можно запустить командой:

```sh
bash CI/render.sh student
bash CI/render.sh full
bash CI/render.sh student
python3 CI/site.py _site-student _site-full
```

Проверка принимает папки готовых сайтов и не зависит от имён исходников,
числа страниц или идентификаторов заданий. При изменении разметки курса
править Python-скрипт не требуется.
