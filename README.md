# Основы кибербезопасности

Материалы перенесены в структуру
[quarto-template-course](https://github.com/Afonenko-Course-Tools/quarto-template-course):
общий портал и пять частей курса.

| Каталог | Содержание |
| --- | --- |
| `theory/` | Исходные главы по криптографии |
| `tasks/` | Лабораторные, порядок работ и черновики контрольных заданий |
| `lectures/` | Презентации лекций |
| `practice/` | Восемь семинаров и преподавательские заметки |
| `handbook/` | Навигация по материалам и библиография |

Лабораторные редактируются в `tasks/lab/`. Условия хранятся один раз,
остальные части курса ссылаются на них. Пустые семинары и контрольные работы
сохранены как заготовки; новые условия не добавлены. Преподавательские черновики
и заметки доступны только в профиле `full`. Для условных блоков используйте
краткую запись `.when-full`.

Отдельный материал храните в именованном QMD-файле, например
`tasks/lab/access-control/ident.qmd`. Каталоги нужны для групп материалов
и ресурсов; `authn.qmd` может соседствовать с `authn/password-protection.qmd`.

## Разметка слайдов

Главная страница связывает тематические блоки с шестью отдельными презентациями
в `lectures/01-intro.qmd` — `lectures/06-attacks.qmd` и существующими материалами
книг. Это маршруты обсуждения; исходные конспекты лекций ещё не подготовлены.
Восемь отдельных семинаров находятся в `practice/sessions/1.qmd` — `8.qmd`.
Их исходная нумерация сохранена; темы и планы пока не заполнены.
Файлы `lectures/index.qmd` и `practice/index.qmd` служат каталогами и сохраняют
прежние адреса ссылок.

Таблицы главной страницы записаны как обычные Markdown-таблицы.
Несколько ссылок в ячейке разделяются ` · `; подпись, ID, ширины столбцов
и классы задаются после таблицы через `: Подпись {#tbl-id ...}`.
В таблицах используйте `{{< xref namespace id "Текст ссылки" >}}`.
В остальных текстах ссылки на материалы курса задаются через `@namespace:id`
или `xref` с явной подписью, без путей к `.html` и `.qmd`.
Библиографические ссылки обрабатываются штатным механизмом Quarto;
ссылка на страницу `references.qmd` сохраняет нативную форму.
Класс `.course-plan` указан в атрибутах самой таблицы плана.
Общий стиль поставляется расширением `course-presentation` версии 2.1.1:
он задаёт ширину, отступы, выделение темы и правила печати.
Нативный класс `.responsive` обеспечивает прокрутку таблиц Quarto.
Авторский контейнер и отдельный CSS страницы не нужны; происхождение
расширения указано в [UPSTREAM.md](UPSTREAM.md). HTML-переносы строк не нужны.

В `lectures/` и `practice/` заголовок `##` начинает раздел, а `###` — слайд.
Раздел может сразу содержать материал или служить заставкой перед первым
слайдом. Вложенные заголовки внутри слайда начинаются с `####`.
Сохраняйте явные `sec-*` идентификаторы для ссылок между частями курса.

В конфигурации Reveal используются `shift-heading-level-by: -1`,
`slide-level: 2` и `navigation-mode: linear`, как в актуальном шаблоне.
Эта настройка действует только на слайды; заголовки книг остаются прежними.

## Сборка

Нужны Quarto **1.10.18** или **1.11.5** и CUE **0.17.1**.
Части theory и handbook используют R с пакетами `knitr` и `rmarkdown`.
Это обычный сайт Quarto. Полные версионированные расширения включены
в репозиторий вместе с зависимостями и лицензиями. Версии и каталоги установки
заданы командами `quarto add` в
[tools/install-extensions.sh](tools/install-extensions.sh), происхождение —
в [UPSTREAM.md](UPSTREAM.md). Обычная сборка использует установленные файлы
и не загружает расширения из сети.

Course v2.1.1 подготовлен и установлен локально. Повторная установка
командой ниже и установка расширений в CI доступны после публикации его
тега; остальные теги уже опубликованы. Для обновления выберите опубликованные
теги в установщике и выполните:

```bash
bash tools/install-extensions.sh
```

Установщик требует Quarto и Bash и может запускаться из любого каталога.
Релиз Course устанавливает Core, Presentation и Navigation одним bundle;
конфигурации частей выбирают используемые фильтры и плагины. Точные версии
каждого пакета указаны в его `_extension.yml`. Собственный реестр поставщиков,
манифесты хэшей, локальные checkout поставщиков и Python для установки не нужны.

Выполните команды из корня репозитория:

```bash
quarto render . --profile student
quarto render . --profile full
quarto preview --profile student --no-watch-inputs
```

Результаты находятся в `_site-full/index.html` и `_site-student/index.html`.
По умолчанию выбран профиль `student`. Course Site собирает пять частей
нативными командами Quarto, объединяет текущие результаты, ссылки QRC и поиск.
Каждая часть запускает штатные проверки Core и QRC и может быть собрана
отдельно из своего каталога, например `cd tasks && quarto render . --profile student`.
Выходные каталоги частей — `_output/student` и `_output/full`.

Сохраняйте `.quarto` и `_freeze` между сборками. После ошибки исправьте исходник
и повторите ту же команду. Полный профиль содержит материалы преподавателя;
для размещения студенческого сайта используйте `_site-student`.

GitHub Actions повторно устанавливает расширения по тем же тегам,
сверяет установленные каталоги с Git и проверяет обе версии Quarto
последовательностью `student → full → student` для PR и ветки `master`.
Публикация студенческого сайта через GitHub Pages включается переменной
репозитория `COURSE_PUBLISH_PAGES=true` при выбранном источнике GitHub Actions.
PR запускает только проверки; профиль `full` не публикуется этим workflow.
