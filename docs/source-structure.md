# Структура и учебные элементы

Курс имеет четыре проекта Quarto: корневой портал, `theory`, `task` и `seminars`.
Состав подпроектов задан в корневом `_quarto.yml`. Теория организована по темам,
банк — в `task/bank/`, назначения — в `task/works/`, слайды — в `seminars/`.
Печатные контрольные находятся отдельно в `control-works/`.

Теория самостоятельна: семинары ссылаются на её понятия, главы теории —
друг на друга и на источники. Обратных ссылок на семинары нет.
Предметная структура:

| Путь в `theory/` | Содержание |
| --- | --- |
| `fundamentals/` | Основные понятия безопасности |
| `legal/` | Правовые требования, классы систем, меры защиты, стандарты |
| `security-center/` | Организация работы центра кибербезопасности |
| `risk-assessment.qmd` | Оценка риска |
| `access-control/` | Аутентификация, авторизация, модели доступа |
| `crypto/` | Случайность, шифрование, хеширование, ключи, подпись, хранение паролей |
| `data-trust/` | Проверка целостности, сертификаты |
| `data-preservation/` | Резервное копирование, восстановление, RAID |

Хранение паролей следует после симметричного шифрования и хеширования.
Подпись Лэмпорта вынесена в дополнительную главу. Оглавления обоих профилей
задаются в `theory/_quarto-{student,full}.yml`.

## Задачи и решения

Банк включается метаданными `task/bank/_metadata.yml`:

```yaml
exercise-bank: true
default-exercise-target: manual
default-exercise-course-role: independent-study
default-exercise-statement-visibility: open
```

Каждая задача имеет сложность `difficulty` и видимость условия
`statement-visibility`, заданные явно либо через банковские defaults.
Оценка времени `time` необязательна. Назначение задачи в работу не создаёт
нового экземпляра условия.

```markdown
:::: {#exr-example difficulty="introductory"}
### Название задачи

Условие и необходимые данные.
::::

::: {#sol-example}
Разбор и ответ.
:::
```

Именованные `#exr-*` и `#sol-*` являются полноценными учебными объектами;
дополнительные распознающие классы не нужны. Решение связывается с задачей
по одинаковому суффиксу в том же QMD. Другой штатный вариант — анонимная
`.solution`, вложенная в задачу. Не связывайте банковский разбор атрибутом `for`.

Публичный разбор требует открытого условия и `course-role="demonstration"`
у задачи. Стадия назначения и настройка раскрытия сами по себе не открывают ключ.
Подборка источников или материалов для чтения оформляется отдельным учебным
блоком с `course-role="reading"`.

## Заголовки и нумерация

Первый заголовок банковского QMD задаёт тему. Содержательные группы нескольких
задач могут иметь заголовки второго уровня. Не создавайте отдельный раздел
для каждой задачи: у задачи уже есть название, номер и адрес `exr-*`.
Первый заголовок внутри задачи задаёт её название; `sec-*` ему не добавляется.

Нумерация разделов и счётчик задач настраиваются средствами Quarto.
В банке `number-depth: 2` ограничивает номера главами и тематическими группами;
`crossref.exr-title` задаёт подпись «Задача». Не пишите номера задач, разделов
или подпунктов вручную. Перечисления оформляйте Markdown-списками с отступами
для вложенных пунктов, а не отдельными абзацами с текстовой нумерацией.

`#sec-*` принадлежит настоящему заголовку, когда разделу нужна адресная ссылка.
Для ссылки на условие используйте `@exr-*`, на смысловой раздел — `@sec-*`.
Не добавляйте HTML-якоря и перенаправления для прежнего расположения текста.

## Работы

Работа задаёт метаданные `assessment` и явный список назначений:

````markdown
---
assessment:
  id: sec-work-example
  kind: seminar
---

# Занятие {#sec-work-example}

::: {.task-items}
1. @exr-example
:::
````

Список `.task-items` перечисляет ID назначенных упражнений. Условия могут
находиться в тематическом банке либо непосредственно в файле работы.
Во втором случае страница объявляет `exercise-bank: true` и
`default-exercise-target: manual`, а список ссылается на её локальные `exr-*`.
Это штатная регистрация учебных объектов Core; отдельные копии условий
в `task/bank/` не нужны. Так устроен `task/works/control-demo.qmd`: пять условий
и связанные материалы для подготовки находятся в самом варианте.

Атрибуты назначения определяют обязательность, способ работы и стадию.
Стадия `demonstration` требует открытого условия, роли `demonstration`
и настоящего публичного решения. Для самостоятельной подготовки по условиям
и материалам стадия остаётся незаданной, а задачи имеют роль `independent-study`.
При переносе сохраняйте семантические ID задач, решений и работ и состав назначений.

## Слайды и рисунки

Слайды показывают материал, необходимые данные и самодостаточный вопрос
без обязательного открытия ссылки или notes. Крупные исследования остаются
в дополнительных задачах. Все семь семинаров используют общие настройки
`seminars/_quarto.yml`: 1600×900, заголовки `##` для тематических групп
и `###` для экранов, сдвиг уровней `-1`, `slide-level: 2`.
Титул задаётся YAML-полем `title`; вручную его не повторяют.
Внутренний заголовок задачи на слайде имеет уровень `####`.

Аудиторные упражнения имеют `target="manual"`, `course-role="discussion"`
и открытое условие. Для включения банковского условия используйте
[подготовку фрагментов](content/visualization-authoring.md): для семинаров она
отбирает только условие, включая вложенные данные, и исключает решения.
Семантика исходной задачи и её решение в банке сохраняются.
Подготовленные файлы в `_prepared/` не редактируются.

Рисунок показывает связь, действие, размещение или изменение.
Перечни и определения остаются текстом; данные для сравнения — таблицей.
Краткие ссылки на подробности оформляются штатным `xref` с текстом `[*]`;
примеры приведены в [руководстве навигации](navigation.md).

Подпись и номер рисунка задаются Markdown-изображением с `#fig-*`, параметром
`fig-cap` ячейки или подписью блока Quarto. Ссылка имеет вид `@fig-*`.
Общее название и номер не дублируются внутри SVG или HTML; содержательные
подписи частей схемы остаются в рисунке. `fig-alt`, `alt` и `aria-label`
задаются независимо от видимой подписи.

Исходники, подготовленные QMD, закрытые решения и Body-пакеты не публикуются
как ресурсы. Правила видимости и экспорта задаёт установленный
[Course Core](https://github.com/Afonenko-Course-Tools/quarto-course/blob/v9.3.4/spec/learning-elements.md).
