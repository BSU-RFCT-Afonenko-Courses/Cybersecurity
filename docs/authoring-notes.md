# Оформление материалов курса

Курс состоит из портала, книги теории, книги заданий и презентаций практики. Условия заданий хранятся в книге `task`; теория и презентации связываются с ними через QRC. Оформление опирается на нативные возможности Quarto и установленное расширение Course Presentation.

Сопоставление выполнено с [опубликованным шаблоном v1.0.0](https://github.com/Afonenko-Course-Tools/quarto-template-course/tree/v1.0.0), указанным в `UPSTREAM.md`, и локальными исходниками на 6 октября 2026 года. Локальный checkout шаблона в соседнем репозитории относится к другой ветке и для этого сравнения не использован.

Ранее согласованные изменения идентификаторов, списка вложенных проектов, определения формата, отображения заметок и общей библиографии не включены в перечень расхождений. Пять компонентов исходного шаблона не требуется восстанавливать: подсказки рассчитаны на нынешние три вложенных проекта.

## Сопоставление с шаблоном

| Область | Шаблон | Текущее состояние и следующий шаг |
| --- | --- | --- |
| Оформление книг | Тема Cosmo и обычные заголовки Quarto | Настроено в теории и заданиях. Дополнительный CSS для стандартных учебных блоков не нужен. |
| Презентации | `##` задаёт раздел, `###` — слайд; Reveal использует стандартную тему | Практика настроена так же. Сохранить эти уровни при наполнении занятий. |
| Учебный маршрут | Портал и план занятия связывают реальные материалы | В портале остались активные ссылки на отсутствующие `lectures` и `handbook`. Цель `tasks:sec-plan` также отсутствует. Удалить устаревшие ссылки или создать соответствующую страницу в текущей структуре. |
| Теория | Объяснение, цели, предварительные знания, пример и вывод | Четыре тематические главы пока содержат краткие наброски на 5–11 строк. Превратить перечисления терминов в объяснения с примерами и проверяемыми выводами. |
| Задания | Канонический блок `exr-*`, требуемый результат и критерии | Работа по резервному копированию уже содержит блок задания и список работы. Вынести результат сдачи в `deliverables`, добавить критерии и конкретизировать способ проверки результата. |
| Состав книги заданий | Главы перечислены в `book.chapters` | Из 12 выбранных страниц одна пуста, девять содержат только заголовок. Пустая страница — `seminar/data-integrity/checksum.qmd`. Заполнить их или временно исключить из публикуемого списка глав. |
| Дополнительные задания и контроль | Страницы включаются явно | Шесть файлов `task/extra` и два файла `task/exam` сейчас не входят в `book.chapters`. Их наличие на диске не означает публикацию. |
| Занятия | Слайды содержат вопрос, действие и ссылки на материалы | Восемь `practice/sessions/*.qmd` пока повторяют один набор общих ссылок. Для каждого занятия указать тему, маршрут обсуждения и конкретные материалы. |
| План курса | Видимая таблица или список маршрутов | Существующая таблица в `index.qmd` закомментирована. Подготовить новый план по текущим материалам; старые ссылки не переносить автоматически. |
| Документация | Названия каталогов и инструкции соответствуют проекту | README и UPSTREAM описывают прежние пять компонентов. README и workflow также ссылаются на удалённый `tools/install-extensions.sh`; инструкции и способ обновления расширений требуют согласования с текущими файлами. |

Подтверждённые совпадения: порядок фильтров Core → Presentation → QRC сохранён; заголовки семинаров имеют явные `sec-*`; книга заданий использует пространство ссылок `tasks`, несмотря на имя каталога `task`. Это допустимо и позволяет сохранить существующие ссылки.

## Ссылки и идентификаторы в материалах

У каждого заголовка, на который будут ссылаться другие материалы, задавайте явный ID. Используйте латиницу в нижнем регистре, цифры и дефисы. Сохраняйте ID при переименовании заголовка или переносе файла.

| Что обозначает ID | Форма |
| --- | --- |
| Тема, раздел или работа | `sec-crypto-random`, `sec-work-data-integrity-backup` |
| Каноническое задание | `exr-lab-data-integrity-backup` |
| Учебный пример | `exm-random-output` |
| Связанное решение | `sol-random-output` |
| Рисунок или таблица | `fig-random-flow`, `tbl-course-plan` |

Не назначайте один ID одновременно заголовку и окружающему контейнеру. Внутри одного проекта одинаковые цели не должны повторяться на разных страницах.

В пределах книги используйте нативную ссылку `@sec-theory-crypto-random`. Между проектами используйте QRC:

```markdown
Теория: @theory:sec-theory-crypto-random.
Условие работы: @tasks:exr-lab-data-integrity-backup.
```

Для явно заданной подписи, особенно в таблицах, используйте shortcode:

```markdown
{{< xref tasks exr-lab-data-integrity-backup "Работа по резервному копированию" >}}
```

Для ссылок на материалы курса не пишите вручную пути к `.html` и `.qmd`. Обычные ссылки на изображения, вложения и внешние сайты остаются обычными Markdown-ссылками. Пространство QRC — имя (`practice`), а не путь (`../practice`).

Сейчас `tasks:sec-plan` встречается в 11 активных ссылках, но такого заголовка среди выбранных для сборки исходников нет. Для восстановления маршрута можно создать план в книге заданий, включить его в `book.chapters` и сохранить ожидаемый ID `sec-plan`. Ссылки портала на `handbook:sec-handbook` и `lectures:sec-lectures` нужно привести к текущим материалам.

## Теоретическая глава

Одна глава раскрывает одну тему. В начале обозначьте, что студент сможет объяснить или сделать после чтения. Затем дайте определения, небольшой разобранный пример, ограничения и итог. Длинные перечни терминов лучше разбивать на связанные абзацы.

Структурный образец:

```qmd
# Генераторы случайных чисел {#sec-theory-crypto-random}

::: {course-role="objectives"}
После чтения вы сможете объяснить основные различия рассматриваемых генераторов.
:::

::: {course-role="prerequisites"}
Для чтения нужны понятия, перечисленные в подготовительных материалах.
:::

## Основные понятия {#sec-random-concepts}

Определение понятия и объяснение его назначения.

::: {#exm-random-output}
Небольшой разобранный пример, иллюстрирующий определение.
:::

::: {course-role="limitation"}
Граница применимости рассмотренного примера.
:::

::: {course-role="takeaway"}
Главный вывод, который нужно сохранить после чтения.
:::
```

Это образец структуры, а не готовый предметный текст. В текущей главе `sec-theory-crypto-random` уже назначен заголовку второго уровня: при использовании образца перенесите существующий ID, чтобы не получить дубликат.

Полезные роли оформления:

| Роль | Когда использовать |
| --- | --- |
| `objectives` | Результаты обучения |
| `prerequisites` | Необходимые знания и подготовка |
| `reading` | Материалы для чтения |
| `takeaway` | Итог раздела |
| `limitation` | Ограничения метода или примера |
| `misconception` | Типичная ошибка понимания |
| `deliverables` | Что нужно предоставить |
| `criteria` | Как оценивается результат |

Добавляйте роли там, где подпись помогает читателю ориентироваться. Не превращайте каждый абзац в отдельный блок.

## Задание и работа

Работа (`assessment`) объединяет задания, а блок `exr-*` содержит само условие. Эти уровни не следует смешивать: название работы, состав работы и условия отдельных заданий имеют разные функции.

Структурный образец для существующей работы по резервному копированию:

```qmd
---
assessment:
  kind: lab
---

# Резервное копирование {#sec-work-data-integrity-backup}

Краткая цель работы и необходимые исходные материалы.

## Практические действия {#sec-lab-data-integrity-backup}

:::: {#exr-lab-data-integrity-backup course-role="independent-study" difficulty="intermediate"}
### Условие работы

Последовательно опишите действия, которые требуется выполнить.

::: {course-role="deliverables"}
Перечислите файлы, результаты наблюдений и пояснения, которые нужно сдать.
:::

::: {course-role="criteria"}
Укажите проверяемые признаки успешного выполнения.
:::
::::

::: {.assessment-items}
1. @exr-lab-data-integrity-backup
:::
```

Для текущего Core у канонического задания обязательны `course-role` и `difficulty`. Допустимые назначения задания: `demonstration`, `discussion`, `independent-study`, `control`. Значения сложности: `introductory`, `intermediate`, `advanced`.

Атрибут `time="30"` означает оценку в минутах; `work-mode` принимает `individual`, `pair` или `group`. Они необязательны. Не задавайте сложность и время блокам вроде `objectives` или `criteria`: это метаданные деятельности. Для блока `reading` доступен `requirement="required"`, `recommended` или `optional`.

Необязательный `target` при отсутствии получает значение `manual`; для обычной работы добавлять его не требуется. Блоки заданий не вкладывают друг в друга.

Перед заданием должен быть тематический заголовок с `sec-*`: Core использует его для определения происхождения задания. Поэтому в образце сохранён `sec-lab-data-integrity-backup` у ближайшего внешнего заголовка.

Для работы доступны `assessment.kind: lab`, `test`, `exam`. В `.assessment-items` нужен один маркированный или нумерованный список, по одной ссылке на задание в каждом пункте. Сам перечень заданий уже существующей работы по резервному копированию оформлен правильно.

## Презентация занятия

При текущих настройках практики раздел задаётся через `##`, слайд — через `###`, внутренние подзаголовки — через `####`. Каждое занятие хранится в отдельном QMD. Слайд должен давать один вопрос, одно объяснение или одно действие, а подробный текст можно размещать в заметках.

```qmd
---
title: Резервное копирование
---

## Разбор работы {#sec-backup-session}

### Что нужно проверить {#sec-backup-session-question}

Как определить, что восстановление завершилось успешно?

Условие работы: @tasks:exr-lab-data-integrity-backup.

::: {.notes}
Пояснение к вопросу и связь с предыдущими материалами.
:::

### Выполнение работы {#sec-backup-session-work}

1. Откройте условие работы.
2. Выполните действия и сохраните наблюдения.
3. Сверьте результат с критериями.
```

Образец показывает способ оформления, а не назначает конкретное занятие этому материалу. Заголовкам, на которые ведут ссылки с портала или из книги, нужны постоянные `sec-*`. Порядковые номера слайдов вручную писать не нужно.

Условие задания в презентации не копируется: достаточно QRC-ссылки и краткого маршрута работы. Атрибут `for` у подсказки или решения связывает их с учебным элементом того же документа; он не заменяет межпроектную ссылку на задание из книги.

## Таблицы и обычный Markdown

План курса оформляйте обычной Markdown-таблицей. Подпись и классы задавайте после неё:

```markdown
| Материал | Где открыть |
| --- | --- |
| Теория | {{< xref theory sec-theory "Теория курса" >}} |
| Задания | {{< xref tasks sec-tasks "Задания и работы" >}} |
| Презентации | {{< xref practice sec-practice "Занятия" >}} |

: Материалы курса {#tbl-course-plan .course-plan .striped .hover .responsive tbl-colwidths="[30,70]"}
```

Число значений в `tbl-colwidths` должно соответствовать числу столбцов. В старой закомментированной таблице портала четыре столбца, а ширин задано пять; при восстановлении плана этот атрибут нужно пересмотреть.

Для изображений задавайте содержательную подпись и при необходимости `#fig-*`. Команды, имена файлов, параметры и фрагменты кода выделяйте обратными кавычками. Последовательности действий оформляйте нумерованными списками, наборы вариантов — маркированными. Между абзацами оставляйте пустую строку; перенос строки внутри абзаца не заменяет новый абзац.

Для повторяемых авторских фрагментов подходит нативный `include`; файлы таких фрагментов называйте с начальным подчёркиванием, чтобы отличать их от самостоятельных страниц. Подключённый фрагмент входит в документ как текст, поэтому уникальность ID проверяется уже после включения.

[Синтаксис Markdown Quarto](https://quarto.org/docs/authoring/markdown-basics.html).

## Что исправить в первую очередь

1. Восстановить или убрать устаревшие ссылки портала; создать выбранный маршрут `sec-plan` либо изменить ведущие к нему ссылки.
2. Заполнить пустую главу контрольных сумм и девять глав заданий, содержащих только заголовки, либо временно исключить их из публикуемого списка.
3. Использовать работу по резервному копированию как образец: добавить результат сдачи и критерии, затем аналогично оформить остальные работы.
4. Наполнить четыре главы теории объяснениями и примерами; сохранить существующие цели ссылок.
5. Заменить одинаковые заготовки восьми семинаров конкретными маршрутами по готовым материалам.
6. Решить, какие страницы из `extra` и `exam` готовы к включению в книгу; самостоятельная страница работы начинается с `#`, а не с `###`.
7. Привести README, UPSTREAM и инструкции CI к фактическим каталогам и способу установки расширений.

Для проверки отдельного материала достаточно предварительного просмотра соответствующего QMD. Для проверки межпроектных ссылок нужна общая сборка: отдельная сборка может оставлять QRC-ссылки на соседние проекты отложенными. После наполнения материалов следует проверить как навигацию и ссылки, так и фактическое отображение страниц и слайдов.

Образцы теоретической главы, работы, презентации и таблицы прошли отдельную сборку в Quarto 1.11.5 с установленными Core, Presentation, QRC и Course Site. Межпроектные ссылки в этом примере разрешились.
