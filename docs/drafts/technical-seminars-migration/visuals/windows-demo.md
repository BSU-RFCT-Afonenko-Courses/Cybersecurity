# Показ прав Windows

Материал В8 для совместного просмотра с Т1 и С4. Состояние на 8 ноября
2026 года: **подготовлен частично**. Три подлинных изображения загружены
из первичных издательских источников и просмотрены. Они показывают
пользователей, группы и окно разрешений, но не образуют полный опыт
с членством и обращениями на одной подтверждённой версии системы.
Собственный захват Windows в этой среде не выполнялся.

## Параметры собственного захвата

Целевая среда — отдельная учебная Windows 11 Pro с локальным томом NTFS.
До подготовки записать фактические **редакцию, версию, номер сборки
и язык интерфейса**; взять их из `winver` и «Параметры → Система → О системе».
Не подписывать будущий снимок конкретным номером сборки до этого шага.
Работать в уже доступной среде, без установки нового ПО.

Параметры изображения: 1920×1080, масштаб Windows 100%, светлая тема,
русский интерфейс, PNG без потерь. Если доступен другой язык или масштаб,
записать фактическое значение в атрибуции. Снимать окно целиком с заголовком,
вкладкой и нужными строками; курсор убрать от текста. Для каждого окна
сохранить читаемый исходник и проверить его в проекторе 1600×900.

Имена ниже — параметры будущего учебного опыта, а не сведения
о состоянии имеющихся компьютеров.

| Объект | Требуемое состояние перед захватом |
|---|---|
| Учётные записи | `demoOwner`, `demoReader`, `demoOther`; все локальные, отдельная служебная учётная запись администратора для подготовки |
| Группа | `demoReaders`; единственный член из трёх демонстрационных записей — `demoReader` |
| Каталог | Новый пустой `C:\AccessDemo-20261108` на NTFS |
| Файл | `Report.txt`, одна строка `Версия 1` |
| Права каталога и файла | `SYSTEM`, локальные `Administrators` и `demoOwner` — полный доступ; `demoReaders` — чтение и выполнение; иных выдач демонстрационным пользователям нет |
| Владелец | `demoOwner` |
| Область опыта | Локальный файл; общий сетевой ресурс не создаётся |

Права настраиваются только у нового учебного каталога. При отключении
наследования проверить сохранение служебного полного доступа и точный
список разрешений. Не менять ACL родительских или системных каталогов.
Не использовать добавочный `Deny`: отсутствие выдачи достаточно
для требуемого опыта. Пароли создаются при подготовке и на снимки
не попадают.

Все членства настроить **до нового входа** `demoReader` и `demoOther`.
Новый процесс должен работать с соответствующим маркером доступа,
а не с повышенным маркером администратора. При изменении членства
завершить демонстрационный сеанс и войти заново; перед повторной
проверкой закрыть открытые файлы. Это устраняет неоговорённое влияние
старого маркера и уже выданного дескриптора.

## Последовательность кадров

| Кадр | Открытое окно и выделение | Что преподаватель устанавливает по кадру |
|---|---|---|
| `windows-demo-version.png` | `winver`, видны версия и сборка | Какая система действительно использована; сохранить для атрибуции |
| `windows-demo-users.png` | Computer Management → Local Users and Groups → Users; видны три демонстрационных имени | Существуют отдельные локальные записи |
| `windows-demo-members.png` | Свойства `demoReaders`; список участников раскрыт | Именно `demoReader` состоит в группе |
| `windows-demo-acl.png` | Свойства `Report.txt` → Security; выбрана `demoReaders`; имя объекта и разрешения читаются | Группе назначено чтение, запись не выдана |
| `windows-demo-advanced.png` | Дополнительные параметры безопасности файла: владелец и все записи | Нет второй личной или групповой выдачи, меняющей вывод |
| `windows-demo-read.png` | PowerShell в обычном сеансе `demoReader`: `whoami`, затем `Get-Content C:\AccessDemo-20261108\Report.txt` | Запрос выполняет нужная запись, чтение успешно |
| `windows-demo-write-denied.png` | Тот же сеанс: `Add-Content C:\AccessDemo-20261108\Report.txt 'Версия 2'` и фактический отказ | Вход и членство не разрешили запись |
| `windows-demo-other-denied.png` | Новый обычный сеанс `demoOther`: `whoami`, затем тот же `Get-Content` и фактический отказ | У другой записи нет установленного пути чтения |

Проверить после неуспешной записи, что файл всё ещё содержит `Версия 1`.
Текст ошибки брать только из реального вывода. Если результат отличается,
сначала проверить маркер процесса, ACL и членства; не подменять вывод
заранее набранным сообщением.

## Порядок аудиторного показа

1. По каталогу записей связать знакомый логин с идентификацией.
   Саму аутентификацию объяснить отдельно: список пользователей не показывает
   предъявление пароля или другого подтверждения.
2. Показать членство и назначение чтения. Попросить аудиторию спрогнозировать
   чтение и запись `demoReader`.
3. После фиксации прогноза показать реальные обращения и сравнить результат.
4. Попросить прогноз для `demoOther`, затем показать его обращение.

Это короткий демонстрационный опыт, а не настройка машин студентами
и не замена основным задачам на матрицу и модели.

## Что решить на рецензии

- Оставить ли три издательских изображения только в пояснительных материалах
  и заменить ли их на единый собственный захват в основном показе.
- Достаточны ли три опорных кадра «пользователь, членство, ACL»
  вместе с двумя результатами обращения для общего занятия.
- Какие фактические версия и язык Windows доступны для такого захвата;
  это техническая предпосылка, а не повод создавать имитацию интерфейса.

До получения собственных кадров пункты захвата не считаются выполненными,
а В8 не объявляется окончательно принятым.
