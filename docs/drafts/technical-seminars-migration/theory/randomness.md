# Криптографическая случайность {#sec-draft-randomness}

Для ключа важно, чтобы наблюдатель не мог практически восстановить
его по доступным сведениям. Длина строки и частоты её символов отвечают
на другие вопросы. Даже длинный результат остаётся уязвимым к перебору,
если возможных способов его получения мало и они известны наблюдателю.

Известный по моделированию генератор может быть удобен именно повторяемостью:
одинаковое начальное состояние воспроизводит опыт. При создании ключа
нужна непредсказуемость для того, кто не должен знать этот ключ.

## Состояние и выход {#sec-draft-random-state}

::: {#def-draft-random-state name="Состояние генератора"}
**Состояние генератора** — сохраняемые данные, от которых зависит
его дальнейшая работа. Начальные данные для создания состояния
обычно называют seed.
:::

Упрощённый шаг детерминированного генератора записывается так:

$$
(S_{i+1}, r_i)=G(S_i).
$$

Здесь $S_i$ — состояние перед шагом с номером $i$;
$S_{i+1}$ — новое состояние; $r_i$ — выданные биты;
$G$ — известный алгоритм перехода и выдачи. При одинаковом состоянии
и одинаковых последующих входах результат одинаков.
Состояние и выданная строка — разные части модели: хороший генератор
не обязан раскрывать своё состояние в каждом выходе.

Краткая связь с известным LCG:

$$
x_{i+1}=(a x_i+c)\bmod m.
$$

$x_i$ — целочисленное состояние; $a$ — множитель; $c$ — слагаемое;
$m>0$ — модуль; $\bmod m$ даёт остаток от деления на $m$.
Если выходом служит полное состояние и параметры известны,
наблюдатель может сам выполнить следующий шаг. Большой период
или равные частоты отдельных значений этого вычисления не отменяют.
Восстановление параметров по числам — отдельное расширение,
а основной вопрос здесь — откуда берётся неизвестность состояния.

## Энтропия источника {#sec-draft-random-entropy}

::: {#def-draft-random-entropy name="Энтропия источника"}
**Энтропия источника** характеризует неопределённость получаемого
значения в заданной вероятностной модели. При оценке для защиты
учитывают сведения, доступные наблюдателю.
:::

Одна из мер — минимальная энтропия дискретной величины:

$$
H_{\infty}(X)=-\log_2\!\left(\max_x\Pr[X=x]\right).
$$

$X$ — случайное значение; $x$ — один из его возможных результатов;
$\Pr[X=x]$ — вероятность этого результата в рассматриваемой модели;
максимум выбирает самый вероятный результат. Логарифм по основанию 2
задаёт единицу измерения — бит. Эта формула описывает выбранное
распределение; при появлении новых сведений о $X$ оценку пересматривают.

Например, у равномерного выбора одного из восьми значений
$H_{\infty}=3$ бита. Если известный алгоритм преобразует такой выбор
в длинную строку, возможных результатов остаётся не более восьми.
Алгоритм может растянуть представление, но детерминированная обработка
не создаёт дополнительной неопределённости о выборе.

Для понимания численной меры достаточно этого примера.
Для реального источника нужна модель измерений: оценки зависимости,
смещения, условий работы и доступного противнику наблюдения.
[NIST SP 800-90B](https://csrc.nist.gov/pubs/sp/800/90/b/final)
разделяет источник шума, обработку и проверки работоспособности;
одна гистограмма выходных чисел не заменяет такую оценку.

## Физический источник {#sec-draft-random-physical}

::: {#def-draft-random-source name="Источник энтропии"}
**Источник энтропии** получает данные из процесса с неопределённостью,
оценивает или контролирует работу источника и при необходимости
обрабатывает измерения для дальнейшего использования.
:::

Физическим основанием могут служить шумовые процессы в электронной
схеме. Важно различать само измерение и последующие вычисления:

| Стадия | Смысл |
|---|---|
| Шумовой процесс и измерение | Дают новые данные с физической неопределённостью |
| Проверки работоспособности | Помогают заметить предусмотренные моделью отказы источника |
| Обработка измерений | Преобразует сырые данные, например уменьшает смещение |
| Обновление состояния | Вводит новые данные в состояние генератора |
| Генерация | Быстро выдаёт нужный объём битов из состояния |

Обработанная последовательность может выглядеть ровнее сырого сигнала.
Это не означает, что обработка сама произвела недостающую энтропию.
Проверки также не дают универсального доказательства отсутствия всех
возможных способов предсказания.

## Аппаратный пример Intel {#sec-draft-random-hardware}

В описанном Intel DRNG источник использует тепловой шум в кремнии.
Измеренные биты поступают в блок обработки; далее подготовленные данные
обновляют состояние детерминированного генератора.
Выдача `RDRAND` идёт из этого генератора, а `RDSEED` предназначена
для получения подготовленных исходных данных, которыми можно
инициализировать другой генератор. Это различие относится к описанной
архитектуре, а не ко всем возможным процессорам.
[Intel DRNG Software Implementation Guide, ред. 2.1, §§ 3.2 и 4](https://www.intel.com/content/www/us/en/developer/articles/guide/intel-digital-random-number-generator-drng-software-implementation-guide.html).

Поддержку инструкций необходимо проверять, а неудачную выдачу учитывать.
Для прикладной программы полезная граница — системный криптографический
интерфейс. Например, Windows предоставляет
[`BCryptGenRandom`](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptgenrandom)
с выбором системного генератора и кодом результата.
Наличие инструкции в процессоре не устанавливает свойства всей программы:
важны также создание состояния, его защита и обработка ошибок.

## Криптографический генератор {#sec-draft-random-csprng}

::: {#def-draft-random-csprng name="Криптографический генератор"}
**Криптографический генератор** выдаёт биты так, чтобы при выполнении
условий его конструкции наблюдатель без необходимых секретных данных
не мог практически отличить выход от случайного или предсказать его
с полезным преимуществом.
:::

Детерминированность совместима с этим требованием: алгоритм известен,
но подходящее внутреннее состояние неизвестно. В конструкциях DRBG
криптографические преобразования связывают состояние, выходы
и последующие обновления. Начальные данные должны иметь достаточную
энтропию, а состояние нужно защищать.
[NIST SP 800-90A Rev. 1](https://csrc.nist.gov/pubs/sp/800/90/a/r1/final)
описывает такие механизмы; окончательная
[SP 800-90C, сентябрь 2025](https://csrc.nist.gov/pubs/sp/800/90/c/final)
рассматривает построения, объединяющие их с источниками энтропии.

Для анализа жизненного цикла состояния полезны три разных вопроса:

1. Можно ли из наблюдённых выходов практически узнать следующий?
2. Что сможет восстановить тот, кто получил внутреннее состояние?
3. Какие свежие данные и предусмотренное обновление нужны,
   чтобы прекратить дальнейшее предсказание после такой утечки?

Если состояние просто скопировано, детерминированные копии с одинаковыми
входами повторяют работу. Если состояние стало известно, продолжение
вычислений без неизвестного противнику входа не возвращает секретность
само собой. Обновление состояния свежими данными источника называется
повторным внесением энтропии, или reseed; результат зависит от конструкции
и качества этих данных. Из одного лишь различия новых входов нельзя
вывести обязательное различие любых двух конечных ключей.

Для ключа проверяют источник, модель состояния и способ применения
выхода. Статистические испытания помогают выявлять некоторые недостатки,
но утверждение о непредсказуемости требует анализа конструкции
и условий её использования.
