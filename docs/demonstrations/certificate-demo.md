# Просмотр сертификата сайта

Сценарий связывает учебную цепочку с реальным окном сертификата.

## Цель показа

Связать поля реального сертификата с тремя участниками учебной схемы:
сайт, промежуточный центр, доверенное основание. После показа студент
должен различать ключ субъекта и ключ проверки подписи издателя,
называть ожидаемое имя сайта и находить конец пути, которому доверяет
данная установка браузера.

## Подготовка преподавателя

1. На компьютере для занятия открыть актуальный Chrome и записать его
   полную версию, ОС и дату показа. Использовать обычный профиль без
   предварительно установленных учебных сертификатов.
2. Открыть `https://www.rfc-editor.org/`. Это выбранный адрес для показа,
   а не обещание конкретного издателя или длины цепочки. Если доступ
   перенаправлен, записать фактическое имя из адресной строки.
3. Убедиться, что браузер установил обычное HTTPS-соединение.
   Если используется корпоративная проверка HTTPS, зафиксировать это:
   браузер может строить путь к локально установленному центру организации.
   В таком случае не приписывать показанную цепочку публичному серверу.
4. Открыть DevTools. В меню команд (`Ctrl`+`Shift`+`P` на Windows/Linux)
   выбрать `Show privacy and security`. В разделе `Security > Overview`
   нажать `View certificate`. Названия команд взяты из
   [официальной документации Chrome DevTools](https://developer.chrome.com/docs/devtools/security/).
   Локализованный интерфейс и окно сертификата могут отличаться;
   путь предварительно проверить на том компьютере, где идёт занятие.

## Что вывести на экран

| Экран | Что показать крупно | Что зафиксировать без догадок |
|---|---|---|
| Адресная строка и окно сертификата конечного сайта | Фактическое имя сайта; выбранный конечный сертификат | URL, имя из `Subject Alternative Name`, поле издателя |
| Детали конечного сертификата | Открытый ключ субъекта и назначение | Название алгоритма ключа; назначение, если оно показано; при сохранении снимка — отпечаток сертификата |
| Иерархия или путь сертификатов в реальном окне | Конечный сертификат, промежуточные центры, выбранное основание | Имена в порядке окна; число промежуточных центров; какой сертификат выбран |
| Выбранный промежуточный сертификат | Его субъект, издатель и разрешение выдавать сертификаты | Где отражено разрешение центра; наличие соответствующих полей в этом интерфейсе |
| Настройки доверия используемой установки | Запись выбранного основания в доверенном хранилище, если интерфейс позволяет её проверить | Проверена ли запись непосредственно; если нет — явно «хранилище не просмотрено» |

Окно просмотра может показывать сертификаты в порядке, обратном ходу
проверки. Преподаватель указывает обе связи: кто указан издателем
сертификата и чей открытый ключ используется для проверки его подписи.
Если конкретное поле не видно, открыть детали; отсутствующее наблюдение
не заменять подписью, нарисованной поверх изображения.

Затем рядом вывести [учебную схему цепочки](../../shared/visualizations/data-trust/static/certificate-chain.svg) с внешней подписью Quarto.
Сопоставить $P$ с ключом сайта, $C$ — с ключом реального промежуточного
центра, $R$ — с выбранным основанием. Если промежуточных центров больше
одного, повторить звено $C$, не сводя реальный путь к трём участникам
задним числом. Подчеркнуть: самоподпись не объясняет доверия к основанию;
оно зависит от настройки проверяющей системы.

## След наблюдения

Сохранить реальные снимки окна конечного сертификата и полного пути
только после проверки читаемости на проекторе. В сопроводительной записи
указать версию Chrome, ОС, дату, фактический URL, выбранный путь и источник
доверия. Для будущего Markdown-изображения название и номер задаёт Quarto;
внутрь снимка не добавляется искусственный заголовок. Персональные сведения
профиля браузера не нужны в кадре.

Если доверенное хранилище не удалось непосредственно просмотреть,
демонстрация подтверждает лишь путь, показанный данной установкой браузера.
Не следует утверждать, что проверена конфигурация всех компьютеров
аудитории. Перечень и названия центров нельзя заготовить как неизменные:
сервер и браузер могут выбрать другой допустимый путь.

## Граница вывода

Показ объясняет принадлежность ключа имени сайта в принятой системе доверия.
Сертификат не доказывает истинность текста страницы. Проверка соединения
также включает подтверждение владения закрытым ключом; на схеме показана
только связь имени и открытого ключа. Возможность отзыва упоминается одной
фразой: система учитывает его по своим правилам. Задачи о сроках,
истечении сертификата и времени подписи в этот показ не добавляются.

Содержательные опоры: [RFC 5280, § 6.1](https://www.rfc-editor.org/rfc/rfc5280.html#section-6.1)
и [§ 4.2.1.9](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.2.1.9).
Перед занятием проверьте сценарий на компьютере преподавателя.

## Подпись программы в Windows

Для второго знакомого примера возьмите уже скачанный подписанный
установщик от известного разработчика. Запускать его не требуется.

1. Откройте свойства файла и вкладку «Цифровые подписи», если она есть.
   Выберите подпись и откройте сведения о ней.
2. Покажите издателя, результат проверки и сертификат подписывающего.
   В пути сертификатов найдите конечного издателя, промежуточный центр
   и доверенное основание; конкретные имена берите из своего окна.
3. Сопоставьте с общей схемой: файл — сообщение, данные подписи — $s$,
   открытый ключ находится в сертификате издателя. Закрытого ключа
   издателя в установщике нет.
4. Сохраните читаемый кадр результата проверки и кадр пути сертификатов.
   Укажите имя файла, версию Windows и дату наблюдения. Если вкладки нет,
   не изображайте её: сведения о подписи можно получить командой ниже
   или выбрать другой подписанный файл.

```powershell
Get-AuthenticodeSignature -FilePath .\setup.exe |
    Format-List Status, SignerCertificate
```

Имя *setup.exe* замените именем выбранного файла. Фактические `Status`
и `SignerCertificate` запишите после выполнения, без заготовленного вывода.
Успешную проверку сопоставьте с ожидаемым издателем; сама подпись
не означает, что программе нужно разрешить любые действия.

Справка: [Get-AuthenticodeSignature](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/get-authenticodesignature).
