# Организация технического блока

Технический блок включает управление доступом, криптографию, доверие
к данным и сохранность данных. [Карта источников](technical-seminars-task-map.md)
связывает действующие главы, банки, слайды и рисунки.
[Контекст аудитории](course-context.md) задаёт предпосылки
и границы глубины. Общие авторские правила находятся в [AGENTS.md](../../AGENTS.md).

## Предметная структура

Теория самостоятельна и первична. Главы организованы по предметам
и зависимостям понятий; семинары выбирают материал и ссылаются на неё.
Обратных ссылок из теории на семинары нет.

| Каталог | Содержание |
|---|---|
| `theory/access-control/` | Аутентификация и отдельная глава об авторизации |
| `theory/crypto/` | Случайность, шифрование, хеширование, подпись, управление ключами, хранение паролей |
| `theory/data-trust/` | Проверка целостности и отдельная глава о сертификатах |
| `theory/data-preservation/` | Резервное копирование и отдельная глава о дисковых массивах |
| `theory/legal/` | Правовые основы и стандарты |
| `theory/risk-assessment.qmd` | Оценка риска как отдельная глава верхнего уровня |
| `task/bank/` | Полные условия и решения |
| `task/works/` | Назначенные работы |
| `seminars/` | Объяснения и вопросы для показа аудитории |
| `shared/visualizations/` | Общие авторские схемы и интерактивные примеры |

Асимметричные механизмы входят в `crypto/` независимо от номера занятия.
Хеширование и симметричное шифрование предшествуют хранению паролей.
При переносе материала обновляются оглавления, ссылки и ресурсы;
устаревшие адреса не сохраняются автоматически.

## Последовательность семинаров

| Семинар | Основной ход |
|---|---|
| **4. Управление доступом** | Процедуры входа → факторы → TOTP/passkey → запрос и монитор → DAC → компилятор → MAC → RBAC → совместные политики |
| **5. Криптография** | Архив → непредсказуемость → источник и состояние генератора → RANDU → ключ → шифрование/XOR → распределение секрета → хеш → парольная запись |
| **6. Доверие к данным** | Проблема общего секрета → пара ключей → шифрование → RSA → длина и стойкость → доверенный хеш → подпись → назначение ключей → издатель → сертификат |
| **7. Сохранность данных** | Нужная версия → виды копий → состав и объём → восстановление → проверка копии → RAID → зеркало → восстановление проекта |

Понятие или правило предшествует вопросу на применение. Условие
содержит необходимые данные, правила и проверяемое действие. Истории
изменений и распределения прав представляются таблицами; схемы
показывают потоки, связи, размещение или изменение состояния.
Решения упражнений на слайды не выводятся.

Слайды всех семинаров используют общий формат 1600 × 900. Название
занятия задаётся `title` в YAML; `##` задаёт тематическую группу,
`###` — отдельный экран, `####` — заголовок внутри упражнения.
Сдвиг заголовков настроен в общем проекте. Основной текст остаётся
в QMD; ссылки на подробности имеют краткую метку `[*]`.

## Авторский цикл

1. Непосредственно прочитать учебную литературу и первичные документы.
   Передать автору точные положения, условия, разделы и короткие цитаты.
   Для PDF различать печатную страницу и страницу файла; HTML не
   приписывать вымышленные номера страниц.
2. Передать Терре цель, предметную основу, границы владения и сохраняемые
   материалы. Построить объяснение от назначения к понятиям, правилу
   и примеру. Сокращение для экрана сохраняет причины и условия вывода.
3. Независимо прочитать источник и итоговую последовательность. Проверить
   предпосылки вопроса, полноту условия и границы утверждений; после
   исправления перечитать затронутый переход.
4. Вычитать заголовки, вводы, подписи и notes на авторские и технические
   ремарки из процесса подготовки. Команды, обозначения и предметные
   условия сохранять по их учебной роли.
5. Согласовать ссылки, ресурсы и назначения. На время общей сборки
   остановить изменения исходников; проверить оба профиля и выдачу.

Опора процесса — [методика Java](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/master/docs/authoring-methodology.md)
и [issue №36](https://github.com/BSU-RFCT-Afonenko-Courses/Java/issues/36).
Регламент выпуска и модельные полномочия другого проекта сюда не переносятся.

## Подготовка выдачи

Авторские ресурсы редактируются в `shared/visualizations/`.
`CI/prepare-course-visualizations.py` материализует их внутри проектов
и подготавливает банковские фрагменты. В семинарных фрагментах остаются
только условия с ролью `discussion` и целью `manual`; вложенные решения
удаляются, заголовки внутри условия приводятся к H4. Обычный отбор
для других потребителей сохраняет разборы. `_prepared/` не редактируется.

Единый курс собирается командами `bash CI/render.sh student` и
`bash CI/render.sh full`, последовательно. Начальные страницы —
`_site-student/index.html` и `_site-full/index.html`. Обычные страницы
доступны локально; интерактивы OJS требуют HTTP-доступа.
Команды проверок и отдельного просмотра описаны в
[руководстве сборки](../build.md) и [руководстве просмотра](../../CI/README-preview.md).
