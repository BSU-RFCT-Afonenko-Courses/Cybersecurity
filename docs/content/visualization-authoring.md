# Авторский интерфейс визуализаций

Предметные вычисления, запросы, объяснения, DOT и SVG находятся в
`shared/visualizations/`. Общая обвязка — в авторском расширении
`extensions/course-visualizations/`. Теория и слайды используют одни исходники.

## Подготовка

Перед рендером `theory` и `seminars` автоматически выполняется
`CI/prepare-course-visualizations.py`. Он запускает построение SVG,
копирует публичные модули в проектный `_prepared/visualizations/`
и выбирает запрошенные банковские условия до инвентаризации Core.
Подготовленные копии не редактируют и не коммитят.

Для отдельной подготовки из корня курса:

```sh
python3 CI/build-visualizations.py
python3 CI/prepare-visualizations.py theory seminars
```

Нужны Python 3, Node.js, Graphviz (`dot`), `quarto pandoc`
и зависимости из `CI/requirements-visualizations.txt`.
Браузер получает готовые SVG и JavaScript; эти средства сборки ему не нужны.

## Статический рисунок

Вложенные главы теории обращаются к локальной подготовленной копии:

```markdown
![Три уровня мандатной модели](../_prepared/visualizations/access-control/mac/static/overview.svg){#fig-mac-overview fig-alt="Процесс L2 и файлы трёх уровней"}

См. @fig-mac-overview.
```

Для `seminars/*.qmd` путь начинается с `_prepared/visualizations/`.
Подпись, номер и ссылку задаёт Quarto. Внутри SVG остаются содержательные
подписи узлов, стрелок и частей схемы. Общий заголовок рисунка там не дублируется.

SVG моделей DAC, MAC и RBAC редактируются непосредственно в `static/`;
блок-схемы алгоритмов — в `graphs/*.dot`. Сборщик преобразует сохранённые
DOT в SVG. Согласуйте идентификаторы групп рисунка с ключами подсветки
предметной трассы. [Структура схем доступа](../../shared/visualizations/access-control/README.md).

## Общий интерактивный фрагмент

Страницы теории и семинаров подключают интерактивные примеры через `include`.
OJS выполняет JavaScript и находится внутри общего QMD-фрагмента. Поэтому
изменение примера применяется ко всем страницам, которые его включают.

Схемы доступа описаны в `shared/visualizations/_dac-example.qmd`,
`_mac-example.qmd` и `_rbac-example.qmd`. Остальные опыты находятся в
`shared/visualizations/fragments/`. Подготовка копирует фрагменты внутрь
каждого проекта; у файлов верхнего уровня убирается начальное подчёркивание.

Во вложенной главе теории:

```markdown
{{< include ../_prepared/visualizations/dac-example.qmd >}}
```

В семинаре:

```markdown
{{< include _prepared/visualizations/dac-example.qmd >}}
```

Новый пример создавайте в общем фрагменте. Например:

````markdown
```{ojs}
//| echo: false
ownMacLesson = await import(await FileAttachment("/_prepared/visualizations/access-control/mac/lesson.js").url())
viewof ownMacRequest = ownMacLesson.macControls()
```

```{ojs}
//| echo: false
//| label: fig-own-mac
//| fig-cap: "Проверка запроса мандатной модели"
//| fig-alt: "Выделены запрос, применяемое правило и результат"
ownMacLesson.macDiagram(ownMacRequest)
```
````

Каждый фрагмент объявляет необходимые ему модули, использует собственные имена
OJS и `fig-*`; его включают один раз в документ. Для второго независимого
экземпляра создайте фрагмент с другими именами. Полный и компактный варианты
LCG используют одну предметную реализацию с разными параметрами отображения.
Гистограмму строит локальная Observable Plot из `vendor/plot.js`; фрагмент
передаёт библиотеку в `lcgTrainer`, поэтому другие примеры её не загружают.

Проектный путь `FileAttachment` одинаков во вложенной теории и в слайдах.
Импорты внутри `.js` разрешаются относительно модуля; SVG загружаются через
`new URL(..., import.meta.url)`. Подпись и номер рисунка задаются параметрами
ячейки Quarto. Внутри виджета остаются данные запроса и объяснения проверки;
общие оговорки под рисунками не дублируются.

## Модели и runtime

У DAC, MAC и RBAC отдельные `model.js` и `lesson.js`.
Предметный `*Trace(query)` возвращает последовательность этапов.
`*Controls(options)` создаёт управление с состоянием
`{query, trace, index, stage}`; смена запроса сбрасывает этап.
`*Diagram(selected, notes)` показывает выбранное состояние и пояснение.

Общие функции находятся в `shared/visualizations/common/runtime.js`:

- `createControls(traceFor, queries, options)` управляет запросом и этапом;
- `prepareSVG(source, keys, result)` подготавливает SVG и его подсветку;
- `renderStage({selected, model, algorithm, notes})` соединяет схемы и объяснение.

Этап содержит `name`, `label`, ключи `model` и `algorithm`, а при необходимости —
результат `allow` или `deny`. Пояснения индексируются по `stage.name`.
Удаление пояснения не удаляет этап и не меняет решение модели.
Runtime изолирует DOM-идентификаторы каждого экземпляра и сохраняет
семантические ключи SVG в `data-key`.

| Предметный модуль | Компоненты |
| --- | --- |
| `access-control/{dac,mac,rbac}/lesson.js` | Управление запросом и пошаговая проверка соответствующей политики |
| `authentication/lesson.js` | Сравнение процедур, регистрация passkey, вход с passkey |
| `crypto/lesson.js` | LCG, отбор параметров по наблюдаемым переходам, изменение битов хеша, парольные опыты, Цезарь, XOR |
| `data-integrity/lesson.js` | Сумма и хеш, шкалы копирования, RAID, коллизия суммы, изменение байта, замена эталона, восстановление XOR |

Учебные опыты не назначают задачи и не сохраняют оценки.
Условия, решения и педагогические роли задаются штатной разметкой курса.
Закрытые ключи и ответы не размещаются в публичных JS, OJS и SVG.

## Условие банка на слайде

Канонический источник — `task/bank/*.qmd`. Для получения конкретных объектов:

```sh
python3 CI/prepare-bank-fragments.py --source task/bank/fundamentals.qmd --id exr-fundamentals-event-or-incident --output seminars/_prepared/bank-fragments
```

На слайде включается подготовленный фрагмент:

```markdown
## Вопрос для аудитории

{{< include _prepared/bank-fragments/exr-fundamentals-event-or-incident.qmd >}}
```

Подготовка выбирает условие и его парное либо вложенное решение,
сохраняет ID и банковские defaults. Остальные задачи и метаданные страницы
не переносятся. Одноимённый объект не включают дважды в один документ.
Обычная подготовка перед рендером определяет необходимые ID по включениям;
отсутствующий или неоднозначный ID останавливает её.

Документ с банковскими фрагментами явно объявляет:

```yaml
exercise-bank: true
default-exercise-target: manual
default-exercise-course-role: independent-study
default-exercise-statement-visibility: open
course-presentation:
  answers: auto
```

Core определяет видимость условий и решений. Раскрытие Presentation
и стадия назначения не меняют доступ к ключу. Смысловые правила блоков
приведены в [руководстве учебных элементов](../source-structure.md).

## Доставка и проверка

В проектах используются `embed-resources: false` и `html-math-method: mathml`.
Публичные `.js` и SVG из `_prepared/visualizations/` включены в ресурсы явно;
подготовленные QMD и банковские фрагменты исключены.
Quarto доставляет статические SVG как обычные ресурсы из `_prepared/visualizations/`.
Фильтр авторского расширения подключает стили; OJS компилирует сам Quarto.

Runtime установленного авторского расширения копируется в
`_prepared/visualizations/common/course-runtime.js`;
проектный вход `common/runtime.js` ссылается на эту копию.
Весь `_extensions` в публикацию не переносится.

Предметные тесты и браузерные сценарии находятся в `CI/visualizations/`.
Проверяйте модели отдельно от отображения, а готовые страницы — по HTTP,
включая оба профиля, несколько независимых экземпляров и доставку
транзитивных модулей и SVG. Порядок сборки и доступные команды описаны
[в руководстве проверок](../build.md).

## Битовое сравнение хешей

Фрагмент `fragments/hash-bit-experiment.qmd` использует `hashBitExperiment()`:
два текстовых входа, Java `String.hashCode` и SHA-256, одинаковое представление
битами и выделение изменившихся позиций. Java-хеш вычисляется по кодовым
единицам UTF-16 с 32-битным переполнением; SHA-256 получает UTF-8.
Стили ограничены классом `.course-viz-hash-bits` в расширении.

## Повторное использование SVG

`crypto/static/symmetric-key.svg` используется обычным изображением в теории
и загружается обоими опытами шифрования. Широкую статическую версию
`symmetric-key-slide.svg` для слайдов создаёт `CI/build-visualizations.py` из
тех же узлов и стрелок. `crypto/static/password-record.svg`
также используется текстом и опытом регистрации/входа. Виджеты клонируют
исходник через `prepareSVG`, получают уникальные ID и меняют только значения
`data-slot`, классы текущей фазы и расположение на широком экране.

Статические файлы показывают общую процедуру и доступны без JavaScript.
Виджеты подставляют значения примера и выделяют выбранный этап. Схема
парольной записи разделяет регистрацию и вход на две дорожки; на узком
экране её область можно прокручивать независимо от страницы. Оформление
управления находится в `browser/cipher.css` и `browser/password.css`
авторского расширения; готовые SVG содержат собственное оформление узлов
и стрелок для самостоятельного использования.

## Предметные статические схемы

`crypto/static/hash-length.svg` сопоставляет разные длины входных строк и
фиксированную длину SHA-256. `hash-security-goals.svg` различает заданные и
искомые значения в трёх задачах поиска. Эти схемы используются изображениями;
повторяемость не требует отдельного рисунка. Принятый битовый опыт объясняет
распространение изменения входа и остаётся самостоятельной демонстрацией.

`randu-planes.svg` показывает два ракурса одного набора точных последовательных
троек RANDU. Геометрическая структура обнаруживает зависимость между выходами.

`crypto/static/key-pairs.svg` изображает пять участников и десять неупорядоченных
пар. Каждому ребру соответствует отдельный общий секрет; подпись рисунка и
ссылка `@fig-crypto-key-pairs` задаются в QMD. Схема используется обычным
Markdown-изображением, а численные сравнения количества ключей остаются
нативной таблицей Quarto.

## Отбор параметров LCG

`fragments/lcg-model-selection.qmd` вызывает `lcgModelSelection()` из
`crypto/lesson.js`. Во вложенной теории фрагмент подключается так:

```markdown
{{< include ../_prepared/visualizations/fragments/lcg-model-selection.qmd >}}
```

Подпись и номер задаёт Quarto через `fig-lcg-model-selection`. Внутри виджета
показываются наблюдаемые переходы, сетка 64 пар множителя и слагаемого, проверки
каждой модели и оставшиеся кандидаты. Модуль равен 16, параметры $a$ и $c$
независимо перебираются от 0 до 7. Переходы $2\to11\to8\to9$ сокращают число
подходящих пар $64\to4\to1$; последняя проверка сохраняет единственную пару.
По ней записывается прогноз 14, после чего раскрывается фактический выход
исходного генератора. Наблюдаемые значения служат ограничениями на модели;
сетка отражает те же проверки и состояние отбора.

Восстановление неизвестного модуля по шести полным выходам остаётся отдельным
математическим разбором в теории и не требует собственного SVG.
