14.1 Дайджест

Чтобы сравнить большой файл с ранее сохранённым эталоном, удобно вычислить компактное значение по всем его байтам. Его можно хранить и передавать отдельно от файла.

Определение 14.1 (Хеш-функция) Хеш-функция преобразует последовательность байтов в значение фиксированной длины — хеш, или дайджест.

Дайджест представляет данные компактным значением для поиска или проверки. У хеш-функции есть следующие свойства:

  • Длина входа. Вход может иметь различную длину, в том числе значительно превышать длину результата. Конкретный алгоритм задаёт допустимый диапазон: SHA-256 принимает сообщения длиной менее 2642^{64} битов согласно FIPS 180-4.
  • Длина дайджеста. Для выбранного алгоритма она фиксирована. SHA-256 выдаёт 256 бит независимо от длины допустимого входа.
  • Детерминированность. Одна и та же последовательность байтов при повторном вычислении заданной функцией даёт тот же дайджест. Это позволяет сравнить результат с ранее вычисленным значением.

При криптографическом применении дополнительно рассматривают лавинный эффект — распространение малого изменения входа по выходным битам — и стойкость к трём задачам поиска: прообраза, второго прообраза и коллизии. Длина дайджеста и детерминированность описывают вычисление; задачи поиска определяют, чему должен сопротивляться криптографический алгоритм.

Возможных входов больше, чем фиксированных выходов, поэтому существуют коллизии: разные входы с одинаковым результатом. Для SHA-256 входов длиной 512 бит уже 25122^{512}, а возможных дайджестов 22562^{256}; некоторым входам приходится соответствовать одному результату.

На Рисунок 14.1 входные строки имеют разную длину, а каждый SHA-256 занимает ровно 64 шестнадцатеричных знака.

Хеш используют, например, для поиска в таблице. Java String.hashCode вычисляет 32-битное целое в арифметике int по кодовым единицам UTF-16: для двух символов это 31⋅код первого+код второго31 \cdot \text{код первого} + \text{код второго}. У Aa получается 31⋅65+97=211231 \cdot 65 + 97 = 2112, а у BB — 31⋅66+66=211231 \cdot 66 + 66 = 2112. Строки различны, хотя их хеши совпали. Хеш-таблица при совпадении хеша сравнивает сами ключи и тем самым различает эти записи. Такой хеш предназначен для организации поиска; его совпадение не доказывает равенство данных.

SHA-256 выдаёт 256 бит — 32 байта, обычно записываемых 64 шестнадцатеричными цифрами. Длина результата и назначение SHA-256 отличаются от 32-битного hashCode.

14.2 Семейство SHA-2

SHA-256 и SHA-512 — криптографические хеш-функции семейства SHA-2. Они вычисляют дайджесты длиной 256 и 512 битов соответственно, то есть 32 и 64 байта. Описание обоих алгоритмов дано в FIPS 180-4. Хеширование детерминировано; для восстановления исходного сообщения по дайджесту ключа расшифрования нет.

14.3 Лавинный эффект

Криптографическая хеш-функция стремится распределять влияние малого изменения входа по всему дайджесту. Это свойство называют лавинным эффектом: при изменении одного бита входа изменения выходных битов исследуют на множестве входов. Отдельная пара показывает лишь собственный результат; стойкость к поиску прообраза или коллизии устанавливают отдельно.

14.4 Стойкость хеша

Пусть известны алгоритм HH и его выходы. Для подходящей криптографической хеш-функции должны быть вычислительно трудны отдельные задачи:

  • Прообраз: по заданному значению yy найти любой вход xx, для которого H(x)=yH(x)=y.
  • Второй прообраз: по заданному входу xx найти другой вход x′≠xx'\ne x с тем же хешем, H(x′)=H(x)H(x')=H(x).
  • Коллизия: найти любую пару разных входов xx и x′x' с одинаковым хешем; первый вход заранее не задан.

На Рисунок 14.2 различаются заданные и искомые значения: при поиске прообраза задан дайджест, при поиске второго прообраза — вход, а при поиске коллизии выбирают оба входа.

Это разные условия поиска. Фиксированная длина результата и лавинный эффект сами по себе не обеспечивают стойкость к этим задачам. NIST выделяет три требования стойкости. Наличие коллизий неизбежно, но для безопасного применения важно, насколько трудно их найти. Хеширование не является шифрованием: у него нет ключа расшифрования, возвращающего произвольный исходный вход.

14.5 Изменение входа

Возьмём байты UTF-8 строк abc и abb, без кавычек и завершающего перевода строки. Последние байты 63 и 62 в шестнадцатеричной записи отличаются одним младшим битом. Их полные SHA-256:

Вход SHA-256
abc ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
abb 715edf8ba8729420cd4d1ce85ed61954a9f531f8c548df728c407effe839296d

В этой паре различаются 124 из 256 выходных битов SHA-256; у 32-битного результата Java String.hashCode различаются два бита. Другая пара входов может дать иное число изменившихся битов. Интерактивное сравнение позволяет изменить вход и наблюдать оба результата.

14.6 Усечение

Для наглядного поиска сократим SHA-256 до первых 12 битов, то есть трёх шестнадцатеричных цифр. Вычисляем хеши UTF-8 строк Файл 0, Файл 1, … без кавычек и перевода строки. На 47-м вычислении, для Файл 46, впервые в этом порядке повторяется префикс 2a5, ранее полученный для Файл 16:

Вход Полный SHA-256 Первые 12 битов
Файл 16 2a5cc51b0a427b54b5e3c069e86df4e8df17a4b021e1bd636710af839b789c7d 2a5
Файл 46 2a5948ed5cf742c52a67e0d7b73e904a55362f778391ed67f6d163014b099a68 2a5

Это коллизия усечённой функции; полные SHA-256 различаются по остальным битам. Усечение оставляет всего 212=40962^{12}=4096 возможных результатов и облегчает поиск совпадения. При проверке каждой новой строки достаточно сравнить её префикс с уже полученными: совпасть могут любые два из них. При проверке заданного файла требуется совпадение именно с его дайджестом; это другая постановка поиска, соответствующая второму прообразу.

14.7 Проверка скачанного файла

Разработчик публикует файл и его SHA-256. Получатель вычисляет дайджест скачанных байтов и сравнивает его с эталоном. При различии хотя бы одно из значений изменилось или вычислено для другого содержимого. Совпадение с доверенным эталоном даёт основание считать файл неизменённым с момента вычисления эталона с учётом стойкости функции; оно не сообщает, кто опубликовал файл.

Если злоумышленник заменил и файл, и размещённый рядом эталон на хеш подменённого файла, сравнение тоже совпадёт. Поэтому происхождение эталона нужно установить отдельно. Например, издатель подписывает список имён файлов и их хешей, а получатель проверяет подпись и связь ключа с издателем; эти действия рассматриваются в главе о цифровой подписи.

Быстрый хеш удобен для больших файлов, но делает дешёвой проверку каждого кандидата пароля. Для сохранения паролей применяют специальную затратную функцию с солью: Глава 18 показывает, как соль и параметры сохраняются в проверочной записи.
